CoinSwitch Support: Diagnostic packet for failing POST /trade/api/v2/order (401 Unauthorized)

Short summary
--------------
We are seeing 401 Unauthorized responses for signed POST requests to /trade/api/v2/order while signed GET requests (for example /trade/api/v2/user/portfolio) authenticate successfully. The client is generating Ed25519 signatures over a canonical message composed of method + path + canonical-json-body (and optionally epoch) and sending:
  - X-AUTH-APIKEY: <redacted>
  - X-AUTH-SIGNATURE: <hex signature produced by Ed25519>
  - X-AUTH-EPOCH: <ms epoch used to sign>

We have instrumented the client to print the exact canonical message and produced signatures, and include reproduction steps and the dump below. Please review server-side logs for the timestamp/epoch and signature below and tell us what canonicalization or header formatting the server expects for POSTs.

Environment
-----------
- Client: Windows PowerShell (user environment)
- Project: D:\peaches
- Script: D:\peaches\newbot.py
- Python: Virtualenv at D:\peaches\.venv
- Key material: API key and secret provided in the environment for diagnostics (we will NOT include the secret in this packet).

What works
----------
- GET endpoints (example: GET /trade/api/v2/user/portfolio) authenticate successfully using the same API key/secret with the same signing function when the client canonicalizes an empty body correctly.

What fails
----------
- POST /trade/api/v2/order returns 401 Unauthorized for the same client signing function (Ed25519, hex-encoded signature) when sending the canonicalized JSON body and headers.
